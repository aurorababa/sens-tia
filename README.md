# SENS-TIA website (static site + Supabase)

Files
- `index.html`, `screening.html`: bilingual (EN/SQ) pages. Generated by `build.js` (edit the text there, then run `node build.js`).
- `assets/style.css`: design (Arial, IHRE/NEUAR blue + orange accent, WCAG AA contrast).
- `assets/config.js`: **you fill this in** (Supabase URL + public anon key, contact email, field dates).
- `sql/01_schema.sql`: database, security rules and the screening function.
- `docs/`: the final PDFs linked from the site (call for participants and information/consent form, v1.0). To update them, replace the files and keep the same names.

## Go live in 8 steps
1. **Supabase**: supabase.com > New project > region **EU (Frankfurt)** > set a strong database password (store it in a password manager).
2. **Database**: SQL Editor > New query > paste `sql/01_schema.sql` > Run. Then run: `insert into public.admins(email) values ('your@email.com');`
3. **Keys**: Project Settings > API. Copy the **Project URL** and the **publishable** key (starts with `sb_publishable_`) or the legacy **anon public** key into `assets/config.js`. Never use or share the `service_role` key.
4. **Test mode check**: until config.js is filled in the screening page shows an orange TEST MODE banner and saves nothing. After step 3 the banner disappears.
5. **Contact + dates**: fill `CONTACT_EMAIL`, `CONTACT_PHONE`, `FIELD_DATES` in `assets/config.js`. Replace remaining `[yellow-style placeholders]` in `build.js` (data controller, compensation answer, IHRE role wording, funder disclaimer, retention period), then `node build.js`.
6. **GitHub**: create a repository, upload everything except `node_modules/`. Settings > Pages > Deploy from branch `main` / root. Your link will be `https://<user>.github.io/<repo>/`. (Optional later: custom domain such as sens-tia.neuar.org.)
7. **Test**: submit 3 test screenings (one eligible, one not eligible, one on a phone, one in Albanian). In Supabase > Table editor > `screening` check that only eligible rows hold contact details and that no health answers are stored. Delete the test rows.
8. **Launch**: add the PDFs, share the link with the social post, add the link to the call document (a QR code will be generated for it).

## Seeing the sign-ups
Supabase > Table editor > `screening` (columns: status, participant_code, notes are yours to edit). Export to CSV from the same screen for backups (do this weekly; free plans may not include automatic backups).

## Privacy and safety notes
- The form calls only the function `submit_screening`; anonymous visitors cannot read or write tables (Row Level Security).
- Eligibility is decided on the server. Health answers are never stored. Contact details are stored only for eligible people.
- Only the public anon key is in the page. Keep the database password and service_role key private.
- Check current Supabase free-plan limits: inactive free projects can be paused, so open the dashboard at least weekly during the study.
- Albanian text is a draft: have a native speaker review it before launch.
- Photos: the site uses original SVG illustrations. To add open-licence photos, use Unsplash, Pexels or Wikimedia Commons, keep the licence/credit, and add `alt` text.
